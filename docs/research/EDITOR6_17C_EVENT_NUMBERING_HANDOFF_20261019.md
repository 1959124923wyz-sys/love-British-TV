## 永久编号，强制规则
1. 每个十年固定以 `1600S-E001`、`1610S-E001` ... `1690S-E001` 为起点，三位数字递增。**入库后永不因为新发现更早年份事件而重排旧ID**。
2. 下一批本世纪新事件按其史实发生年份所属十年，取该十年原文件中已出现的最大 `Exxx` 加一：如1600年代现有13条，下批第一条用 `1600S-E014`，不把旧 `1600S-E001` 换给新发现的1600年史事。
3. 界面按 `year/date_label` 排序，而非按新增编号排序；历史时间的自然顺序与编目ID独立。
4. 原 `research_event_id` 永久保留 `A:<original>` / `B:<original>` / `C:<original>`；用来去重和核对回原始资料。跨世纪 `arc_id` 永久追踪长期进程；母专题使用 `E6-Txx`，**不**以事件编号替代进程编号。
5. 不把格伦科原出版ID `E6-GLENCOE-1692` 改为 `1690S-E043`；这是一条**原有ID特例**，1692年只出现一次。研究 `A:1692-GLENCOE-KILLINGS` 不得再次出现在正式数据库。
6. 来源键按十年 `1600S-S001` 等分别管理，后续增加新来源按十年最大号递增；已批准事件的 `source_ids` 可以增加，不可改写原件元数据伪装获得新的阅读深度。
7. 同一历史过程的海上截获、运输、登陆等可以是不同事件，但 `related_crosskeys` 与航次ID必须互联并解释不同阶段，不得重复累加人数。
8. 如果发现严重错误，保留编号并标注撤回/已修订和纠错史；绝不通过悄悄删行造成未来编号复用。
