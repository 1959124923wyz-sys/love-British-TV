# 17世纪长篇专题交互返工：逐字对齐16世纪故事与地图联动
**2026-10-21，编辑7｜分批保存于GitHub PR #198**

## 根本缺陷
用户实测爱尔兰1642—1698专题页面发现**只有整块纯文章，缺少16世纪故事正文中的金黄色事件超链接**。对照 `data/stories/munster-desmond-1579-1586.json`、`data/stories/drake-panama-mule-train-raid-1572-1573.json`、`data/stories/hawkins-lovell-atlantic-enslavement-1562-1569.json` 与 `js/history-stories.js`，原架构支持在文章段落里嵌入 `[[事件ID|显示文字]]`：
- HTML为带 `data-story-event` 的 `.story-event-link` 按钮（金色虚线下划线）；
- 单击经过285毫秒区分双击后查找史料事件→切换时间轴年份→沿 `atlasStoryBridge.focusEvent()`→ `map.panTo([lat,lng])` 平滑移动镜头；**保持文章可读且不更改地图缩放**；
- 双击进入事件档案，按钮返回先前专题；从专题返回最初入口事件应恢复原年份。
- 但此前已上线五篇17世纪文章的 **sections[].paragraphs 均为0个此类记号**。
- 同时 `app.js` 的 `atlasStoryBridge.eventById()` 没有查找加载在 `serialPreviewByDecade` 的1600—1699全部十个decade：即使往正文添了链接，只要链接到当前年代以外的事件就返回null，什么也不会发生。这是用户直观感受到的真正系统缺陷。

## 为什么不是每一句、每一节都硬加超链接
- 16世纪范本只把**与地图中可查的具体历史事件一一对应**的正文片段设为可点击，不是随便把所有地名变成“外部网页链接”。
- 格伦科早期1690年没产程序目前缺单独地图事件，巴巴多斯1688年奴役法规还缺具名地图事件，皇家非洲公司的1681年阿戈纳女王以及一些有名无坐标的公司航次等亦需日后研究。此时不得为了链接数量而把原文链接到错误年份、错误港口或者臆造历史事件。
- 现有爱尔兰部分法规事件的位置为立法机构参考城市，并**非整岛土地被夺取的地籍位置**；地图移动必须带着原有标注不确定性。东印度公司商馆与皇家非洲公司沿岸堡垒均不意味着内陆主权。
- 图片、图标、路线、政治边界不在本次返工范围；尊重现有双开关“版图／事件”和桌面优先需求。
