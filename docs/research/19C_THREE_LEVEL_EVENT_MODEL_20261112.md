## 三层结构

1. **Theme / 大专题：** 一个殖民制度、战争系列、经济剥夺体系、区域长期征服或土地丧失的完整故事。文章可以覆盖几十年，内部按历史转折讲述背景、军事行动、地方抵抗、资本／土地收益路径、政治后果；地区差异不能被抹平。
2. **Event Block / 地图事件区块：** 同一历史局部地区、明确时段和相互关联的行动。某三年间殖民军焚毁十座村庄，应优先提出一个（或依据行动地区划分几个）区块，显示「某地区连续焚村与掠夺」一个事件说明，内部保留十村原记录。重大独立战役、可准确定位的屠杀可单独成事件；不为每条小记录造一块面。
3. **Evidence Node / 细节证据：** 单次袭击、村名、强征记录、地方证言、调查文件、后世研究或史料目录；每条有原始ID、日期文本、具名地、行动主体、来源编号与实际阅读深度。后世档案日期不能被当作历史事件年份。

## 合并的必要条件

只有**时间接近 + 地域确属同一局部 + 同一行动链/政策实施过程 + 各节点有可核来源**时，才准汇集为一个地图事件；仅同省、同世纪、同类型犯罪或两个地点相距近不够。多个地方无确切历史范围，先保留为多点/具名地提示或纯文章，不能凭现代行政边界自动画Polygon。

对作者与受害者、企业武装/正规军/定居者/地方盟军分别归责；被一次袭击多次记录的死者不能叠加计算。调查报告、史料目录、议会答询进入事件的 `evidence_node_ids` 或 `source_ids`，不因报告刊登日期创造一个新的地图袭击点。

## 地图审批与公开呈现

- **候审状态** `research_only`：`geometry=null`；已提出的地名列表仅为人工核查入口。
- 只有地点证据的事件使用Point；有证先后顺序才可建议LineString；有具名局部反复军事行动及依据的事件，经GIS审核后才可制作淡填充、**虚线**军事影响区。
- 军事影响区必须有 `historical_boundary_confirmed:false`、`territorial_claim:false`、`area_sqkm:null`、`exclude_from_area_aggregation:true`、`mapping_method`、`named_anchors`和可追溯来源；不与真实殖民统治区混在同一图层。
- 不编造死亡、受害者、净利润、边界、航线与面积。1900年及后续的暴行只能进入其真实年份，不能提前在1899地图可视化。
- **前台应简洁：** 一个聚合区块配一个事件标题和一段客观概述。精度评语、GIS限制、未核坐标等技术备注保留后台和可展开学术档案，禁止重复铺满面向读者的界面。
- 悬停右栏事件时，对应区块外缘发光；点击事件/地块都能打开同一档案。多区块重叠时保留逐个选中路径，避免大层盖住小层。无需改造手机端。
- 正式长篇复用16世纪已上线专题的 `[[EVENT_ID|自然语言]]` 链接；点击事件切年份、地图定位，双击进入原事件并能返回，**目标ID必须已登记Atlas且确实对应本句史实**。

## 生产者工作清单

**A/B/C历史调查员：** 继续按原区域搜集资料，先提出地方性“事件集合”并保留细节节点、出处、各自行动主体；只交候审地名与制图建议，不替GIS宣称控制区。

**专题编辑：** 以宏观主题为母篇写连贯故事，明确哪些事件必须单列、哪些小型劫掠/强征/焚村按同一行动链并为一个事件；对拟合并区块逐项签字。

**GIS：** 审核历史地名、具体锚点、来源和活动范围；没有可依据历史图件/具名地区的边线，仍旧保持空几何。绘图时把 `related_event_ids` 与专题ID保持可逆关联。

**前端与主编：** 按阶段导入：先来源与事件块，再Atlas年表，最后专题文章及交互测试。未完成 `source_verified → geo_verified → editorial_approved → published` 的阶段不能自动发布。每批桌面Chromium验收后才称“已上线”。
