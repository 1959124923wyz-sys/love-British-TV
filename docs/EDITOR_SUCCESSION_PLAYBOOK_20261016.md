# 爱英TV｜主编接班手册与实战经验（2026-10-16）

> **接班第一句话：直接读 GitHub 当前 main 与本文件，不要仅凭旧聊天的“已上线”判断版本。** 历史真实性优先于产量；用户不懂编程，实际代码操作都由负责主编在 GitHub 完成。本手册仅写工作方式与可恢复点，最终版本须以合并状态、运行日志和 Pages 部署结果为准。

## 一、用户真正想要的作品
- 这是一个从1497年开始逐年推进、面向**第一次学习历史的读者**的英国海外扩张、战争、殖民掠夺与抵抗动态地图。不是数据库后台可视化演示，也不是给观众看的历史GIS专业论文。
- **地图先讲位置与过程，长篇二级资料库讲事件的前因、人物、战争经过和结果。** 长篇标题优先“时间＋公认战名”，没有公认名称就用准确、简短、通俗的描述；不要捏造专有战名。
- 用户明确不喜欢“对地图来说……”“读者需要区分……”“不能由此……”“图钉不是……”等反复教观众如何理解地图的说教。长篇和一级子事件都**只讲历史故事**；研究限制、坐标精度、来源访问层级放在 `reading_note` / `map_note` / `geo_precision` / `source_ids` / `data/historical-detail-notes.json`。不要因此隐藏重大历史争议，只须自然地一句讲清。
- 当前批准深色地图界面、按年渐进出现和数字聚合。长文事件内链 `[[事件ID|显示名称]]`：**单击定位并自动切换到事件年份，双击子事件打开详情，返回要恢复原子事件与历史阅读位置**。没有可信坐标只在小窗显示材料。严禁在未获批准时重造侧栏与时间轴。
- 英王/英军、盖尔领主、苏格兰王室、法国援军、地方议会、商人、原住民必须分清，尤其**苏法军围沃克堡不能算英军烧掠；1522莫尔莱法国军民反击不能算英军暴行**。

## 二、必读的代码与历史治理规范
1. `AGENTS.md`：唯一入门与控制区年度继承规则，1707年前苏格兰不得归入英王版图。
2. `docs/APPROVED_MAP_INTERACTION_STANDARD.md`：数字聚合、独立SVG点、点击规则及用户批准的UI。
3. `docs/MAJOR_HISTORY_STORY_PILOT.md`：**2026-10-16起的正文去说教规范**，早期试点段落中“需要手动切年”等旧解释已被新版本主动切年功能取代，取其最新规则。
4. `docs/HISTORICAL_SPATIAL_NARRATIVE_STANDARD.md`、`docs/HISTORICAL_SPATIAL_REVIEW_CHECKLIST.md`：点/线/面来源，短时劫掠不自动产生政治占领面。
5. `docs/MAJOR_STORY_BACKLOG_1497_1599.md`：50专题索引；状态以 `data/stories/index.json` 和实际 main 为准。
6. `docs/RESEARCH_TERRITORY_CONTINUITY_PLAYBOOK.md`、`data/chapters.json`：十年边界不能重置，事件发生时间与实际控制存在时间不同。

## 三、代码地图：接班从哪里改
- `data/stories/index.json` 是二级专题**唯一发布索引**。每篇 `data/stories/*.json` 用 `sections[].paragraphs` 写故事、`source_keys` + `sources` 管依据、`related_event_ids` 关联全站真实事件。只写文件不登记索引，用户便找不到入口。
- 各年代 `data/atlas-1497-1509.json` 到 `data/atlas-1590-1599.json` 的 `events` 及 `routes` 是地图事实。当前地图正式共十章，第一章1497—1509已视觉合并。新增事件务必 `id` 唯一、`year` 正确、`source_ids` 可在对应章 `sources` 找到。
- `data/historical-detail-notes.json` 保留每个新地点的研究记录。源引用、历史主体、现代参照坐标与古地理不确定性在这里留给后人，而不是反复放正文。
- `app.js`、`js/history-stories.js`、`css/history-stories.css` 控制阅读交互；不要为了补几件事改动大段已批准的UI。
- 端点有据而真实道路未知的路线用 `route_kind:'documented-endpoints-connection'` 和 `valid_years:[年份]`；加载端会按年份闸门展示。**仅能连史料指明的端点，不能连现代最快路径假作古代军道**。
- 史料未证的历史疆界允许淡色虚线地理研究区域但 `historical_boundary_confirmed:false`、`territorial_claim:false`、`area_sqkm:null`、`exclude_from_area_aggregation:true`。**不能把战火影响区算成英王控制面积**。
- 加来城市实际控制时序必须保持到1558年1月、吉讷及Hammes随后失守；具体港堡地点与整片加来Pale历史土地权利不是同一种多边形。英苏边界未证不画实线。

## 五、重要测试教训（来自连续四批专题发布）
1. **必须先改数据，再改旧测试中写死的年度事件数量。** 例如1512新史事会影响1513累计数字；章节新增事件会影响本章任一年总数，不能删历史来让断言变绿。更好的测试是“旧ID仍在＋新增ID合法”，而不是永远固定旧数量。
2. **新的行动关系线会让旧航线测试误报**。已有1527年约翰·拉特海洋航线，1521年萨里陆军线必须区分 `route_kind`／`id`，不能只按 `routes.length===1` 判断海上路线。
3. **跨章回退常看到旧章原有航线**。浏览器测试不能断言“回到1507年所有航线都消失”；正确要求是“未来1512/1516年的新增战线不泄漏到1507年”，原卡博特方向线应留。
4. **跨年阅读不只是向未来跳**。以前文章链接只能切到更晚年份，已修成点文内事件无论早晚均切到相应年份。未来更改务必跑浏览器回归确认不会倒退。
5. 新增GeoJSON feature后，旧代码曾硬性要求6个影响区而拒绝载入整层；现已改为基于 `metadata.feature_count` 等合理校验。以后不要回到“硬写固定Feature数量”的做法。
6. 真浏览器测试也要检查返回原子事件，有一次仅因中文标题预期与实际不同导致失败。尽量核对稳定 `event_id` 与DOM结构，而不要过度依赖中文全名是否完全一致。
7. 同地点的多个历史事件可以使用数字聚合，不要制造重复大图标。未证坐标保留“现代城镇参考”，不要把现代同名旅游城堡当1522年实际遗址。
8. 研究完成就**分批提交独立Git分支**，并记录PR、提交SHA及CI状态。长工作遭中断通常只是回复传输超时，GitHub已有提交仍在；恢复时先读远端，不要用对话里的旧草稿覆盖新提交。

3. 以 **GitHub Actions最新分支HEAD SHA** 核对所有门禁为success，再建PR或审查现有PR，保持主分支保护；只在与主分支无冲突且所有部署门禁通过时合并。用户已明确说“优先上线”，不需要因C级海岸资料不足阻止合并。
4. 合并后必须检查主分支 `.github/workflows/pages.yml` **conclusion=success**，以及远端正式站点 `https://1959124923wyz-sys.github.io/love-British-TV/`。绝不可把“GitHub已提交”说成“正式已上线”。
5. 如果因并行其他智能体提交 main 而合并冲突，**保留分支并先同步差异**，不要强推覆盖他人成果。无法确认时留下确切分支和失败门禁，让下一主编直接接续。
