# 爱英TV｜历史版图长期交付与上线验收制度

**版本：2026-10-13，适用于此后所有新年代；1540—1549为真实已有成果的历史基线，不能假装旧截图验收已签署。**

**本制度解决的问题**：大量史料在研究PR中得到，却没有进入地图；曾经用城堡点连线和任意多边形伪造“实际占领”；新年代重置上一年代控制区；前端图层和数据相互遮挡；研究员说“已经交付”而主编尚未审核，用户以为已经上线。

## 一、四级明确状态（不得混用）

| 状态 | 必须有的可检查实物 | 不等于什么 |
| --- | --- | --- |
| **研究候审** `research_candidate` | 研究PR、来源表、逐年控制台账、至少审查点位与地理精度、可导入数据、疑点 | 未进入主站，不等于用户可见 |
| **主编已集成** `editor_integrated` | 主编选择采用记录，地图GeoJSON/Atlas数据确实出现在`main`；原有Stable ID无故丢失数为0 | 不等于浏览器上线，也不等于历史边线精确 |
| **视觉验收通过** `visual_verified` | 重要年份实际截图或可核的浏览器测试证据；版图、事件两个独立开关、放大缩小与日期变化全测；编辑签名 | 只跑过JSON语法检查不能写通过 |
| **已上线且核实** `released_verified` | 主编批准、Actions检查成功、Pages部署成功、实际网站URL和现场回访 | PR合并和Pages workflow排队中都不能标上线 |

主编/维护者每次宣布某章“完成”必须同时写明目前处于哪一状态。GitHub交接里**没有可追溯证据的“已完成”“全部上线”无效**。

## 二、以后每个十年必有的地图实物

调查员负责将史实转成**真实可读取的数据**，而不是只写一份史料综述：

1. **完整年末台账**：本十年每个年份一份`year_end_snapshot`；每处前期`stable_id`必须判为继续、失去、换手、争议或资料不足。保留“最后文献记录年”和“真实失去控制年”的区别。
2. **控制变化包**：明确地点、年份／可证月份/日期、旧/新控制者、控制性质（法权、军管、暂时行动、仅声索）、`source_ids`、GIS可信度和不确定性；确保关键年份前后的地图颜色和标记有正确增减。
3. **GeoJSON**：确凿堡垒用遗址Point，路线用证实方向的LineString；古代真实Polygon只在确有历史疆界证据与授权时使用。**不准用缓冲圈、现代县界、据点凸包、补给线宽度充当已证英国国土**。未知边界用虚线或无面，任何未知面积必须为`null`。
4. **独立研究源表**：官方古迹地名定位、档案原件、近现代研究、网页转载等分层。对每一个主张注明原文确切支持何事实，若是同一原件的转引不得当成两个独立第一手证据。保留旧地图扫描/再制图版权审查。
5. **待查疑点**：没有确凿年月日、堡址、军控范围不能默默丢弃，也不能伪装为无变化或英国继续驻军。研究员离任只需把遗漏问题与索引交给下一个调查员。

统一复用既有 [跨十年历史控制规范](RESEARCH_TERRITORY_CONTINUITY_PLAYBOOK.md)；**不要为不同章节反复设计不兼容的新字段**。

## 三、主编可执行的标准动作

**研究PR → 主编挑选数据 → 预览 → 审核 → 正式合并 → Pages现场核实**：

1. 主编在 `editorial/cartography/DELIVERY_BOARD.json` 找到当章状态与研究PR。
2. 从 `editorial/cartography/templates/CHAPTER_CARTOGRAPHY_RELEASE_TEMPLATE.json` 复制一份章节审核卡到 `editorial/cartography/releases/YYYY-YYYY.json`。早期已上线章有“历史基线卡”，以后的**1550年代起必须按新标准填写**。
3. **先合史料来源，再合地图数据**。来源缺失则暂不合并相应史事；既有Atlas事件ID及`stable_id`须去重；不可把作者的“可能”“拟建”“接近”提升为已证实际统治。
4. 每一条新增/消失/撤军要在审核卡的 `material_changes` 写明`year`、`control_class`、`map_layer`、`source_ids`、`geometry_status`。史料只能证明军事方向，不能记作“已证整个面”。
5. **先验关键年份再合主站**：必须检查年代首尾、重大扩张/收复年，分别在桌面及手机视图截图留证；检查「版图」「事件」独立/同时显示、国家底色、驻军环、虚线、蓝紫交战区与点击史料。不能因圆圈太粗就把所有城堡连接成紫色领土。
6. 将浏览器证据/报告的有效URL、实际CI运行链接、主编审核人和日期写入审核卡；确认未解决问题合理保留、没有致命史学错判，才把`release_stage`更新为`release_approved`。
7. 合并主分支后由原有 Pages 工作流验证；**只有网站真实核实，才可把看板标为`released_verified`**。如果Actions失败/页面图层不显示，状态回退并留问题单。

## 四、自动门槛真正检查什么

`scripts/validate_cartography_delivery.py`（只用 Python 标准库）已纳入已有的三项CI流水线，不增加独立重复工作流：

- 检查每条`DELIVERY_BOARD`候审卡是否有真实文件、章节身份和下一行动。
- **从1550年开始**，任何进入 `data/chapters.json` 且`status=published`的新章节，必须在`releases/YYYY-YYYY.json`中存在`release_approved`或`published_verified`审核卡。
- 新章需有已纳入Git仓库的Atlas、Source Registry、年度快照、地图Delta文件；全部年份需连续，不许只有一个十年终态。新发布状态记录及GeoJSON的`source_ids`须能查到源。
- 真实古边界Polygon若允许实心或统计面积，必须有历史边线真伪确认与可引用批准来源。**仅是参考图形的Polygon禁止声称面积**；路线宽度不能统计英国领土。
- 真实新章在发布前，桌面+移动端都需真实浏览器证据链接、所有关键年份已测试、独立的版图/事件图层验证、CI成功执行链接、主编具名审核/日期。
- 以上约束若未通过，则既有 [Approved map UI contract](../.github/workflows/approved-map-ui.yml)及 [Publish historical atlas](../.github/workflows/pages.yml) 对该版代码检查失败。浏览器烟雾测试在新Atlas/版图数据变更时纳入PR验收范围。
- **不能自动查清历史真实**：机器只会阻止缺失字段、错误数据类型、无来源ID、明显越权的“推测面积”和未经记录的发布，不能取代史料考证与人工审图；链接也需主编亲自确认真实可看。

**既有六章不被新流程追溯认定为已视觉验收**：1497—1549保留为传统基线，以免仓库过去的工作误因后来加了规则而全部停摆。后续各章不得利用历史豁免。

## 六、自动检查之外唯一需要仓库拥有者设置的保护

**GitHub Actions检查若不设为合并所必需的Required status check，仍可被有权限的人跳过**。本次编辑工具只能修改代码和工作流，不能直接设置仓库分支保护。请在仓库GitHub `Settings → Rules → Rulesets` 为 `main` 启用“Require pull request before merging”及“Require status checks to pass”，至少把常态会运行的 `Approved map UI contract / check-approved-interaction` 设为必须通过；避免要求只在部分文件修改时运行的浏览器smoke workflow，否则可能误拦无关研究PR。另可开启主编的单人批准。设置完后的机制才接近严格技术门禁。

**用户不需要写任何代码**：以后用户只需说“推进第N章地图并按交付制度验收”，调查员自动按上述规范保存支线和数据；主编自己完成审核与网站发布。未经网站视觉确认的成果，绝不向用户说成已经上线。
