## 已确认P1交互缺陷与修复

### 1. 手机上历史事件列表实际被CSS隐藏

`style.css`旧款`@media(max-width:680px)`中存在`.sidebar .event-list{display:none}`（同一规则连章节事实和导语也隐藏），后来暗色新版样式没有覆盖。**这是代码确认且真实Chrome复现的可见性故障**，不是历史GIS坐标不精确。观众在小屏幕即使打开侧栏，也不能从列表选择事件。PR #86中用更晚加载的暗色样式明确恢复事件列表、事实区和章节简介显示，并折叠首屏篇幅较长的章导语，腾出事件列表选择空间。

### 2. 手机初始左栏占掉地图主要视野

小屏`max-width:980px`原本把左侧栏作为覆盖式浮层，但默认`workspace`并无`sidebar-collapsed`。首页第一眼被侧栏占据，且原`togglePanel()`函数没有可见操作入口。PR中手机默认关闭侧栏，头部设置能触发的`☰ 事件`按钮；开档案时收起左栏，防止两侧覆盖式抽屉堆叠。桌面继续保留原有常驻侧栏。

### 3. 触屏用户难以使用双击定位

原规范仅允许左侧列表的`dblclick`事件定位，鼠标悬停提示指出双击，但触屏使用者难发现、键盘用户也没有等价入口。PR新增每条具名有位置事件的资料卡按钮`◎ 在地图上定位`。**只有明确点按钮才执行现有panTo，不更改年份、不自动放大；没有有效坐标或未来未发生则禁用。**移动端定位后自动收起详情，真正露出被高亮的地图；桌面保留详情。原单双击、事件数字聚合、两只正式历史图层开关完整保留。

## 有仪器输出的浏览器验收

`scripts/browser_map_ux_audit.py`经GitHub Actions在Selenium + 真正的Chromium运行，不用手工猜测屏幕状态：

| 浏览视口 | 验收重点 |
| --- | --- |
| 1440×950（桌面Chrome） | 原左栏可见、单击事件仅阅读、详情按钮不改年/缩放、保留右档案 |
| 820×1024（平板模拟触屏） | 事件菜单和侧栏抽屉、事件按钮、读完回图 |
| 390×844（手机模拟触屏） | 首次地图无遮挡、点击事件菜单能看到列表、资料卡定位后归还地图 |
| 375×667（小屏模拟触屏） | 相同的完整用户旅程；确保按钮/地图图层和定位高亮仍存在 |

测试通过条件：左栏默认折叠；移动菜单具有有效ARIA状态；旧CSS`display:none`不得再隐藏事件清单；点选历史事件后不能同时覆盖两个抽屉；位置按钮必须产生地图单点/聚合高亮；地理缩放和当前年保持；原有「版图」「事件」仍能正常开启。每次运行将截图和视口几何参数留存，供维护者检查真实像素。

补充：这证明上述用户路径运作，**不是所有型号手机、所有浏览器和全部历史年份均已验证**。

## 后续按真实体验而非猜测排查（本PR不冒进）

| 优先级 | 真实体验方向 | 应如何证明需要动手 |
| --- | --- | --- |
| P1 | 手机低屏高时三级时间轴遮住历史地理点 | 对320×568、375×667、landscape对比截图，测量地图可操作可视面积与时间轴重叠比，再决定是否将世纪导航收为可展开行 |
| P1 | 历史事件过多时，世界比例尺点位过少，观众误会“这一年没发生什么” | 记录同年事件总数、当倍率实际可见图标数与可见聚合数；若严重不匹配，提供不误导的简短缩放提示而非堆大量永久标记 |
| P2 | 时间轴连续拖动／自动播放是否卡顿 | 在Chromium统计逐年DOM/Leaflet更新耗时及最长帧阻塞，再在证据支持下增加合帧调度或缓存；避免为了速度缓存错误年份图层 |
| P2 | 各类点/线/面是否抢点击，历史抽屉是否挡关键地点 | 浏览器真实指针elementFromPoint检查英国驻军标识、反抗事件点、虚线影响面和航线Stroke的点击优先级；保持原文档批准的无多余背景浮窗样式 |
| P2 | 图例不易理解 | 对普通读者做简易点线面含义任务，确认他们能区分临时袭击、影响区、真实主权后，再改文案/图标；不因为传播性修改事实分类 |

研究地理原则不变：以城市、岛屿和地区的大致可信位置为足够的公众地图入口；不凭虚线Polygon称完整实际占领，不使用现代古迹保护边界替代战争外边界，不为了“冲击力”虚构受袭面积。
